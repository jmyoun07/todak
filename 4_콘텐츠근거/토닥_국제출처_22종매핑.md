# 22종 부작용별 최적 출처 확정표

## 0. 먼저 — 이 결정을 좌우하는 게이트 2개

**게이트 A: 앱의 수익 모델.** Cochrane(한국어 PLS 포함)·대한감염학회 FN 지침은 모두 **NC(비상업)** 조항이다. 앱이 유료·광고·기업 마케팅이면 **Cochrane 전면 사용 불가**가 되고, 그 순간 "이 대처법이 근거 있나"에 답할 자원은 NCCIH(퍼블릭도메인) 하나만 남는다. 아래 표의 보조출처 절반이 이 결정 하나에 매달려 있으므로 **콘텐츠 수집 착수 전에 확정할 것.**

**게이트 B: 이미 확보한 종양간호학회 가이드라인은 CC BY-ND다.** ND = 재구성·요약·발췌 각색 불가. 즉 이 자료는 "앱 UI 문구의 원료"가 될 수 없고 **원문 그대로 인용 블록**으로만 쓸 수 있다. 국내 실행 지침의 핵심 자산인데 각색이 막혀 있다는 점이 이번 설계의 가장 큰 제약이며, 이 때문에 **환자용 실행 문구의 골격은 NCI Side Effects 허브(퍼블릭도메인)로 가져오고 국내 수치·연락체계만 종양간호학회를 인용으로 병기**하는 구조가 사실상 유일한 해법이다.

| **9** | **DailyMed 벌크 ZIP + `/history`** | 자체 DB 구축 시 API 호출 제한 회피. **개정 이력**으로 "이 부작용 경고가 언제 추가됐나" 추적 — 식약처·심평원에 없는 축. |
| **10** | **ONS PEP 6단계 등급 체계** | 텍스트는 못 쓰지만 **증상×중재×6단계 등급 매트릭스 구조**가 우리 앱 설계와 가장 유사. 자체 rubric의 국제 정합성 확보용 벤치마크. |

**도입하지 않기로 확정: NHS(깊이 부족·NCI로 완전 대체), MedlinePlus(health IT 적재 금지), FAERS 수치(왜곡), NCCN/ESMO/MASCC/ASCO/CRUK텍스트/Macmillan/BCN/MSKCC 텍스트(전부 링크·인용만).**

## 5. 한국어판이 있는 자료 (번역 부담 소멸 여부)

| 자원 | 한국어 | 재사용 | 실익 |
|---|---|---|---|
| **Cochrane PLS** | ★있음(정식 지원 언어, 누적 61,000건+) | ⚠️ CC BY-NC만, ND 제외 | ★**유일하게 "한국어 + 재사용 가능"이 동시에 성립.** plain language 원칙으로 이미 작성돼 앱 톤에 바로 붙음 |
| **MSKCC PEIL 한국어**(124건, '화학 요법 부작용 관리' 등 11개 부작용) | ★있음 | ❌ | 텍스트 적재 불가. **한국어 의학용어 대조·톤 참조 + 딥링크**로만 |
| **NCCN Guidelines for Patients 한국어** | ★있음 | ❌ 최강 제한 | **외부 링크만** |
| **ESMO 유방암 환자안내서 한국어 PDF** | ★있음 | ❌ 사전허가 필요 | 딥링크 + 인용. ESMO는 번역 파트너십에 개방적이므로 중장기 접촉 가치 있음 |
| **Komen 한국어 브로셔** | 있음 | ❌ | **부작용 자료 아님**(검진·자가인식). 우리 용도 무관 |
| NCI / NCCIH / openFDA / EMA / MASCC / ONS / CRUK / Macmillan / BCN | 전부 없음 | — | **자체 번역 + 의학 감수 필요** |

**결론: 재사용 가능한 한국어는 Cochrane PLS 하나뿐. 나머지 한국어 자원(MSKCC·NCCN·ESMO)은 전부 링크·용어대조용.** 주력인 NCI 허브는 한국어가 없으므로 **번역·감수 공정이 프로젝트의 실질 병목**이며, NCI 번역본에는 "NCI does not endorse this translation" 문구가 반드시 붙어야 한다.

## 6. API로 자동화 가능한 것 vs 수동

| 영역 | 자동화 | 방법 |
|---|---|---|
| **부작용 빈도 %** | ★완전 자동 | openFDA `drug/label.json` → `adverse_reactions_table` HTML 파싱(caption에서 시험명·N, 행에서 부작용명·%) → 22종 사전 매핑 → 캐시. API key 시 120,000 req/day |
| **라벨 개정 감시** | ★자동 | `effective_time`/`version` diff, DailyMed `/spls/{SETID}/history` |
| **전량 오프라인 적재** | 자동 | DailyMed 벌크 ZIP(일간·주간·월간 증분) |
| **약제명 정규화** | 자동 | RxNorm REST(`/rxcui?name=`) — 인증 불요. 단 **한국어 매핑 없음** → 식약처 제품코드와의 연결은 수동 |
| **EU 빈도 범주** | 준자동 | EMA Medicines Excel 다운로드 → PDF URL 수집 → PDF 파싱 |
| **NCI 허브 본문** | 반자동 | 공식 API 없음. HTML 스크래핑 또는 **NCI Digital Media Syndication** 신청 |
| **Cochrane PLS** | ❌ 수동 | 리뷰별 라이선스 육안 확인이 법적 전제. API로 대체 불가 |
| **국내 자료 전부** | ❌ 수동 | 식약처·심평원·농진청·학회 자료 모두 기계판독성 낮음 |

**필수 구현 주의 3가지**
1. 라벨 표는 시험별·용법별로 여러 개 → **"단독 vs 병용", "조기 vs 전이" 메타데이터를 반드시 함께 표시.** 숫자만 떼면 오정보.
2. 표 항목명이 라벨마다 다름(Hot flashes / Hot flush / Vasomotor) → **동의어 사전 필수.**
3. FAERS는 절대 %로 노출 금지 — 내부 신호 탐지 전용 플래그로 격리.

## 7. 여전히 자체 작성해야 하는 것 (어떤 자료로도 안 채워짐)

1. **"언제 병원에 연락하나"의 한국식 체계** — 외래 vs 응급실 vs 병동 핫라인 구분. NCI/NHS의 연락 기준은 영미 의료체계 전제라 그대로 못 씀. **22종 전부 해당.**
2. **공백 7종의 본문** — 방사선피부반응·표적치료피부반응·수족증후군·심장기능저하·관절통·골밀도감소·체중변화. 이 중 앞 3종은 Cochrane에도 전용 리뷰가 없고 NCI도 Skin and Nail Changes 1개 페이지에 3종을 통합해 놓아 개별 깊이가 없음.
3. **국내 약제·제품명·급여 여부** — 완하제, 지사제, 요소크림, 구강세정액, 질보습제, 비호르몬 안면홍조 약제, G-CSF, 비스포스포네이트.
4. **국내 미도입·비급여 중재의 현실 안내** — 두피냉각, 광생체조절, CBT-I. 국제 근거만 보여주면 "왜 우리 병원엔 없나" 혼란 유발.
5. **한식 기반 식이 조언** — 미각변화·체중변화. 농진청 + 자체.
6. **자체 근거등급 rubric** — ONS PEP 6단계를 **구조만 참조**하고 텍스트는 전부 새로 씀.
7. **전 각색물의 의학 자문 검수** — NHS가 명시하듯 "각색 순간 원 기관의 임상 승인은 소멸"한다. NCI·Cochrane 각색분도 동일 원리. **면책 조항 + 국내 자문의 검수는 선택이 아니라 요건.**

## 9. 한 문장 결론

**새로 도입할 가치가 확실한 것은 4개뿐이다 — NCI Side Effects 허브(환자 실행형 본문 15종, PD), openFDA `adverse_reactions_table`(빈도 % 백본, CC0, API 자동화), Cochrane 한국어 PLS(근거등급 + 번역비 0, 단 비상업 앱 전제), NCCIH(비약물 근거 판정, PD).** 나머지 국제 기관(NCCN·ESMO·MASCC·ONS·CRUK·Macmillan·MSKCC)은 **전부 링크·인용 자원**이며 콘텐츠 소스가 아니다. 등급·국내 규범·전화상담·국내 식이는 **이미 확보한 것으로 충분하고 추가 조사는 종료**한다. 진짜 작업량은 새 출처 확보가 아니라 **NCI 번역·감수 + 공백 7종 자체 집필 + 22종 전부의 한국형 연락 기준 작성**에 있다.
