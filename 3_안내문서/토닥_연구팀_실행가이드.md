## 0단계 · 지금 바로 — 키 발급 (총 40분, 개발이 이것만 기다립니다)

받은 값은 전부 `유방암\_키모음.env` 파일을 메모장으로 열어 `=` 뒤에 붙여넣습니다.
이 파일은 카톡·메일로 보내지 않습니다.

### 0-1. 수파베이스 — 서버·DB (10분, 가장 먼저)

1. supabase.com → Sign in (당봄케어 때 계정)
2. **New Project** 클릭
3. Name: `todak` / Database Password: [Generate] 누르고 **즉시 복사** → `SUPABASE_DB_PASSWORD=` (나중에 다시 못 봄) / Region: **Northeast Asia (Seoul)**
4. Create → 1~2분 대기
5. 왼쪽 맨 아래 ⚙ **Project Settings → API**
6. 저장: **Project URL** → `SUPABASE_URL=` / **anon public** 키(화면에 따라 "Publishable key") → `SUPABASE_ANON_KEY=`
7. ⚠ `service_role`(Secret) 키는 복사하지 않기 — 서버 전용

### 0-2. 카카오 (10분)

1. developers.kakao.com → 로그인
2. **내 애플리케이션 → 애플리케이션 추가하기**
3. 앱 이름 `토닥` / 회사명: 본인 성함 가능 / 카테고리: 건강 계열 아무거나
4. 만든 앱 → **앱 설정 > 앱 키**: **REST API 키** → `KAKAO_REST_API_KEY=` / **JavaScript 키** → `KAKAO_JAVASCRIPT_KEY=`
5. **제품 설정 > 카카오 로그인** → 활성화 **ON**
6. 여기까지만. Redirect URI·동의항목·비즈앱 여부는 연동 단계에서 Claude가 값을 주면서 같이 처리
   (네이버·이메일 가입이 있어서, 카카오는 이메일 없이 연결해 **비즈앱을 피하는 설계**도 가능 — 연동 때 결정)

### 0-3. 네이버 (5분)

1. developers.naver.com → 로그인 (사업자 불필요)
2. **Application → 애플리케이션 등록**
3. 이름 `토닥` / 사용 API: **네이버 로그인** / 제공 정보: **이메일 주소 = 필수** 체크
4. 환경: **PC 웹** / 서비스 URL: 임시 `http://localhost` / Callback URL: 임시 `http://localhost:3000/callback` (진짜 값은 나중에 수정)
5. 저장: **Client ID** → `NAVER_CLIENT_ID=` / **Client Secret**([보기]) → `NAVER_CLIENT_SECRET=`
6. **멤버관리 탭 → 테스트 아이디**에 본인 네이버 아이디 등록 (개발 중엔 이 아이디만 로그인 가능)

### 0-4. 구글 (10분)

1. console.cloud.google.com → 로그인
2. 상단 프로젝트 드롭다운 → **새 프로젝트** `todak` → 만들기 → 프로젝트 전환 확인
3. 메뉴 → **API 및 서비스 > OAuth 동의 화면** → 시작하기: 앱 이름 `토닥`, 지원 이메일 본인, User Type **외부(External)**
4. **앱 게시(프로덕션 전환)** 버튼이 보이면 누르기 — 기본 정보만 쓰는 앱은 심사 없음. 테스트 모드로 두면 참여자 이메일을 일일이 등록해야 함
5. **사용자 인증 정보 → + 만들기 → OAuth 클라이언트 ID** → 유형 **웹 애플리케이션**, 이름 `todak-web`, 리디렉션 URI는 비워두고 만들기
6. 저장: **클라이언트 ID** → `GOOGLE_CLIENT_ID=` / **클라이언트 보안 비밀** → `GOOGLE_CLIENT_SECRET=`

### 0-5. OpenAI (5분)

1. platform.openai.com → 로그인 (당봄케어 계정)
2. ⚙ Settings → **API keys → Create new secret key** (`todak`) → 뜨는 즉시 복사 → `OPENAI_API_KEY=`
3. **Billing**: 결제수단 확인
4. **Limits**: Monthly budget **$40** / 알림 **$20** 설정 → 예산 초과 원천 차단

### 0-6. 공공데이터포털 (이미 신청 완료 — 키 복사만)

1. data.go.kr → 마이페이지 → **개인 API인증키**
2. **일반 인증키(Encoding)·(Decoding)** 복사 → `DATA_GO_KR_KEY_ENCODING=` / `DATA_GO_KR_KEY_DECODING=`
3. 승인 후 1시간~하루 뒤 활성화가 정상

**✅ 0단계 완료 기준**: `_키모음.env`에 10줄이 채워짐 → Claude에게 "넣었어" 한 마디.

## 1단계 · 개발 3주 동안 병행 (개발과 무관하게 진행 가능)

### 1-2. 0·4·8주 설문 폼 만들기

- 측정도구 7종: EORTC QLQ-C30 · QLQ-BR23 · MDASI-K · PHQ-9 · GAD-7 · eHEALS · SUS
- 구글폼 등 온라인 폼으로. 문항 입력이 고되면 Claude가 만들어 드림 (도구 원문만 전달)
- 응답과 연구등록번호가 연결되도록 폼 첫 문항 = 연구등록번호

### 1-3. 연구등록번호 규칙 정하기

- 예: T-001 ~ T-036, 등록 순서대로
- 번호↔실명 대응표(명부)는 **오프라인(잠금 보관)** — 앱·서버에는 번호만
- 앱 DB에 번호를 넣는 것은 연구팀 전용 권한으로 만들어 둠(절차는 Claude가 안내)

### 1-4. 연구팀 문의 연락처 확정

- 문의용 전화·이메일·응대 가능 시간 → Claude에게 전달
- 받으면: 도움말·계정 화면 연결 + 설치 안내문 빈칸 기입 (Claude)

### 1-5. 1577-9740 발신 테스트 (5분)

- 평일 낮 전화 → 암생존자통합지지센터 연결·안내 절차가 앱 문구와 맞는지 확인

### 1-6. 모집 문서에 문항 2개

- "휴대폰 기종(갤럭시/아이폰/기타)" + "아이폰이면 iOS 버전(설정>일반>정보)"

### 1-7. 주차별 확인 역할 (각 30분)

- 1주차 말: APK 설치 → 가입·로그인 되는지
- 2주차 말: 기록 저장·복약 체크·알림 수신·AI 상담
- 3주차 말: 전체 흐름 + 간편 로그인 3종
- 이상한 화면은 스크린샷으로 (그동안 해오신 방식 그대로 — 그게 가장 효과적이었음)

## 2단계 · 배포 직전 (3주차 말 ~ 추석 전)

### 2-1. 네이버 실서비스 전환 검수

- developers.naver.com → 토닥 앱 → **애플리케이션 검수 요청**

### 2-2. 릴리스 서명키 백업

- Claude가 서명키 파일(.jks)을 만들면 → **서로 다른 2곳에 보관** (예: USB + 개인 클라우드)
- 분실하면 기존 설치 위 업데이트가 영구히 불가능 (당봄케어 인계문서의 🔴 경고와 동일)

### 2-3. 시험 사용 3일 (본인 + 지인 2~3명)

- 진짜 참여자처럼: 가입 → 프로필 → 기록 3일 → 복약 체크 → AI 질문 5개 → 알림 수신
- 확인 포인트: 막히는 곳 / 이해 안 되는 문구 / 알림 오는 시간 / 어색한 화면
- 발견사항은 모아서 한 번에 전달 → 수정 → 재배포 (이 단계 수정은 부담 없음)

### 2-4. 실기기 확인

- 본인 갤럭시: APK 설치 전체 흐름
- **아이폰 1대**(지인 10분): 사파리 → 홈 화면 추가 → 실행 → 알림 허용

### 2-5. AI 품질 시험 (Claude와 함께 30분)

- 예상 질문 30개 세트(Claude 준비)를 실제로 던져 답변 확인
- 판정 기준: 진단·응급판정 안 하는지 / 119·병원 연락 안내가 제때 나오는지 / 말투

### 2-6. 개인정보처리방침 확정

- Claude 초안 → 교수님과 확정 → 앱 화면 교체(Claude)

### 2-7. 등록 방문 리허설 1회

- `토닥_설치안내문_참여자용.docx` + 세팅 순서로 처음부터 끝까지 한 번
- 갤럭시 설치(1분) + 아이폰 홈 화면 추가(30초) + 알림 허용 + 배터리 "제한 없음" + 로그인 확인

## 3단계 · 연구 8주 운영

### 3-1. 참여자 등록 (0주차, 1인당 ~15분)

1. 동의서 서명 → 연구등록번호 부여(명부 기록)
2. 앱 설치(기종별) + 알림 허용 + 배터리 제한 없음
3. 가입 도와드리기 → 연구번호 입력(연구팀 절차)
4. 기본 사용법 안내: 오늘 기록 1회 같이 해보기 + AI에 질문 1개 같이
5. 0주차 설문 실시

### 3-2. 4주·8주 설문 발송·회수

- 폼 링크 발송(문자·카톡) → 미응답자 개별 연락 (연구 설문 안내는 허용 — 앱 복약 독려 메시지와는 다름)

### 3-3. 주 1회 백업

- Claude가 만든 백업 스크립트 실행(더블클릭) → 백업 파일을 연구용 폴더에

### 3-4. 문의 대응·수정 배포

- 참여자 문의는 확정한 연락처로 응대
- 앱 수정이 필요하면 Claude에게 → 수정 → 버전 올려 빌드 → 참여자 앱에 "새 버전 받기" 배너가 뜸(재설치 안내 불필요)

### 3-4-1. 참여자가 동의를 철회하겠다고 연락해 왔을 때 (동의 기록 처리)

앱과 알림 서버는 참여자별로 **가장 최근 동의 기록 한 줄**(consent_records 를 consented_at → id 순으로 최신 것)만 봅니다.
그래서 예전 줄에 철회 날짜를 적어도 아무 효과가 없습니다. **철회 줄을 새로 하나 추가**하세요(기록은 고치지 않고 쌓는 방식).

수파베이스 대시보드 → SQL Editor 에서:

```sql
-- 1) 참여자 찾기 (참여자가 가입한 이메일로)
select id, email from auth.users where email = '참여자가 가입한 이메일';

-- 2) 철회 줄 추가 — 위에서 찾은 id 를 넣으세요
insert into public.consent_records
  (user_id, doc_version, terms, privacy, health_info, location, notifications, withdrawn_at)
select user_id, doc_version, terms, privacy, health_info, false, false, now()
from public.consent_records
where user_id = '위에서 찾은 id'
order by consented_at desc, id desc
limit 1;
```

추가하면 이렇게 됩니다.
- 알림 서버(push-send)는 바로 그 참여자에게 알림을 보내지 않습니다. 폰에 예약된 복약 알림은 참여자가 다음에 앱을 열 때 지워집니다.
- 사용기록(접속·정보 열람)은 늦어도 30분 안에 남지 않게 됩니다.
- 다음에 로그인하면 약관 동의 화면이 다시 뜹니다(다시 동의하지 않으면 앱을 쓸 수 없음).
- 이미 모인 자료를 지우는 일은 이것과 별개입니다. 계획서의 철회 자료 처리 절차를 따르세요. 앱 '계정 관리'의 **계정·기록 삭제 요청**은 보호책임자 메일로 오고, 연구팀이 직접 지워야 합니다(앱에서 바로 지우는 기능은 없음).

### 3-5. 위기 대응 준비

- PHQ-9 위험 응답 시 연락 절차(계획서 기재 절차)를 연구팀 내부에서 1회 리허설
- 담당자·연락 순서를 종이 한 장으로 정리해 보관

### 3-6. 월 1회 지출 확인

- platform.openai.com → Usage에서 월 사용액 확인 (한도 설정돼 있어 초과는 불가)
