## 2. 시스템 구성

```
[갤럭시]  토닥.apk ──┐
                     ├── 수파베이스(무료) ── Auth(이메일·카카오·구글)
[아이폰]  웹앱(홈화면) ┘        │              DB(기록·복약·대화·사용로그)
                               │              Edge Function ── OpenAI GPT
                               │                        └──── 심평원 API(병원·약가)
[알림] FCM(안드로이드) / 웹푸시(아이폰) ← 서버 스케줄
[위치] 기기 안에서만 — 서버로 전송 없음
```

- 프론트: 정적 HTML 89화면 + app.css + app-device.css(실기기 오버라이드). 프레임워크 없음.
- 아이폰 웹앱 호스팅: Vercel/Cloudflare Pages 무료 서브도메인 (커스텀 도메인 불요 확정).
- API 키 보관: 클라이언트에 OpenAI/심평원 키를 넣지 않는다 — 수파베이스 Edge Function이 대리 호출.

## 4. DB 스키마 v1.1 (`supabase_schema.sql`)

| 테이블 | 내용 | 비고 |
|---|---|---|
| profiles | 이름·생년월일·연구등록번호·치료단계·아형·병기(들은 값)·동반질환·관심 부작용 | 가입 트리거로 자동 생성 |
| checkins | 날짜별 기분(1~5)·증상·강도·메모 | (user, date) 유니크 |
| medications | 약 이름·용량·시간표·출처(ocr/manual) | |
| med_logs | 날짜·슬롯별 복용 체크 | 순응도 산출 원천 |
| chat_messages | AI 대화 원문 | **회원 계정 데이터 — 연구 자료 아님** (계획서 명시) |
| app_events | 이벤트명만 — **허용목록 6종 CHECK · 삽입 전용**(수정·삭제 불가) | 연구용 사용기록 원천 · 로그 무결성 |
| consent_records | 동의 버전·항목·시각·철회 시각 — 삽입 전용 | 연구 동의 입증 |
| push_subscriptions | 기기별 FCM 토큰·웹푸시 구독 | 알림 발송 대상 |

전 테이블 RLS "본인 행만". 위치 테이블 없음(설계 원칙).
추가 보호: `med_logs`는 복합 FK로 남의 약 참조 차단 · `research_code`는 컬럼 권한으로 클라이언트 수정 불가(연구팀 service role 전용) · profiles에 치료 주기(`treatment`)·알림 설정(`notif_prefs`) jsonb.

## 5. 기능별 구현 방식 · 상태

(2026-08-31 기준 — ✅ 구현·검증됨 / 🔜 설계 확정·미구현)

**로그인 🔜** — 수파베이스 Auth. 이메일(비밀번호 재설정 링크), 카카오·구글 OAuth(수파베이스 내장 프로바이더). **네이버는 수파베이스 내장이 아님** → Edge Function이 네이버 OAuth를 대행하고 Admin API로 세션 발급하는 커스텀 연동(+1일). 휴대폰 본인인증 없음.
주의: ① 카카오 이메일 수집은 비즈앱 전환 필요할 수 있음(당봄케어 경험) — 네이버·이메일 가입이 있으므로 카카오는 이메일 없이 연결하는 설계도 검토 ② 네이버는 개발 단계에선 등록한 테스트 아이디만 로그인 가능 — 참여자 배포 전 **실서비스 전환 검수**(간단, 로고·서비스URL 제출) 필요.

**AI 상담 🔜** — Edge Function `chat`: 시스템 프롬프트(안전규칙+콘텐츠 요지, 캐싱) + 최근 대화 + 질문 → GPT. 응답 필수 요소(계획서 안전성 기준): 진단·응급판단 대행 아님 / 의료진 우선 / 심각·긴급 시 119. 금지: 용량·중단 등 치료 결정 제공, 응급 여부 판정, CTCAE 등급 판정, "악화/호전" 표현. `app_events`에 질문 '수'만 기록(원문은 chat_messages, 연구 미사용).

**복약 알림 🔜** — 사용자가 앱에서 직접 설정하는 기능성 알림(연구진 발송 독려 메시지 아님 — 계획서 문구와 구분). FCM 토큰을 profiles에 저장, 수파베이스 Cron(pg_cron)이 시간표대로 발송. 아이폰은 홈화면 웹앱의 웹푸시.

**약 사진 OCR 🔜** — 카메라 촬영 → Edge Function이 OCR API 호출 → 약 이름·용량만 반환, **이미지는 처리 직후 폐기**(화면 고지와 일치: "확인 화면을 닫는 순간 삭제"). 실패 시 직접 입력(58화면) 폴백. 시간 부족 시 v1.1로 연기 가능(직접 입력 존재).

**근처 병원 🔜** — 심평원 병원정보 API를 Edge Function이 지역 단위로 캐시 → 기기가 목록을 받아 **기기에서** GPS와 거리 계산. 좌표 업로드 금지(위치정보법 면제 조건이자 화면 고지 "휴대폰 밖으로 보내지 않아요"의 이행).

**전화 브레이크 ✅** — 화면에 내장 완료(15개 화면 · dialog 접근성 포함). 추가 구현 없음.

**화면·APK 껍데기 ✅** — 89화면 유동화(267건 검사)·APK 빌드·에뮬레이터 구동·아이콘. `allowBackup=false`(건강정보 클라우드 백업 차단).

| DB에 컬럼 없는 채 새 서버 배포 → 500 → **전 사용자 로그인 튕김 (2회 발생)** | 스키마 변경은 **항상 DB 먼저**, `if not exists`로 재실행 안전(적용됨). 배포 순서: ① DB ② 서버 ③ 확인 ④ 앱 |
| 서버 일시 장애·5xx에 앱이 로그인 상태를 바꿔 튕김, 동의가 조용히 철회됨 | **5xx는 상태를 바꾸지 않는다** — 재시도 안내만. 로그아웃·동의 변경은 성공 응답에만 |
| 동의를 화면에서 체크만 받고 서버에 저장 안 함 → 나중에 이력 없음 수습 | `consent_records` 삽입 전용 테이블로 처음부터 저장(적용됨) |
| 삼성 절전·배터리 최적화가 백그라운드 동작을 죽여 **5개 버전 연속 수정** | 복약 알림은 서버 발송 FCM(고우선순위)로 설계. 설치 안내문에 배터리 최적화 예외 단계 포함(적용됨). 2주차에 삼성 실기기 알림 지연 시험 |
| OpenAI 호출 실패가 500으로 번짐 | AI 상담 실패 시 **앱은 정상 유지** + "잠시 후 다시" 안내, timeout 명시, 실패 시 대체 문구 |
| versionCode 중복으로 스토어 반려 | 직접 배포도 동일 — **같거나 낮은 versionCode는 덮어 설치가 거부됨.** 업데이트마다 +1 (빌드 절차에 포함) |
| 서명키(jks) 분실 = 업데이트 불가 + 파트너 승인 무효 | 3주차 릴리스 키 생성 즉시 **2곳 이상 백업**. debug 키 배포 금지(재설치 충돌) |
| 감사에서 걸린 3종: 개인정보처리방침(PIPA 30조)·오픈소스 고지·소셜 로그인 버튼 브랜드 규정 | ① 정식 처리방침 화면(연구 시작 전) ② **OSS 라이선스 고지 화면**(Capacitor 등) ③ 카카오·구글 실 연동 시 **공식 버튼 리소스**로 교체(현재 이모지 버튼은 시안용) |
| 배포 후 실사용 피드백 라운드가 3개 버전 연속 | 3주차에 연구팀 시험 사용 기간(최소 3일)을 일정에 확보 |

## 8-2. "앱 수정 폭풍" 대비 구조 (당봄케어 빌드 이력 분석, 2026-08-31)

당봄케어는 git 시작 전 **빌드 ~50회**, 이후 4일간 릴리스 4버전. 수정의 대부분은
① 화면 문구·간격·배치(코드로 그린 화면을 실물 보고 고침) ② 만든 기능 삭제(MedicalGoalScreen -239줄)
③ 로그인·동의 흐름 재작업 ④ 삼성헬스 연동 ⑤ 규정 후행 대응이었다.

토닥이 같은 폭풍을 피하는 구조:

| 당봄케어 수정 원인 | 토닥 구조 |
|---|---|
| 화면을 코드로 먼저 만들어 실물 보고 수정 (수정 1건 = 빌드 1회) | **시안=실물 동일 파일** — 문구·배치 수정은 이미 HTML 단계에서 수십 라운드 소진(v1.7→현재). 남는 화면 수정도 빌드 3분 |
| 요구 확정 전에 만든 기능을 통째로 삭제 | 기능 범위 명세서로 확정. (토닥도 성분표 OCR 화면을 만들었다 지웠지만 HTML 단계라 비용 0에 수렴) |
| 로그인·동의 흐름 반복 재작업 | 동의 화면·저장 구조(consent_records)·게이트 규칙을 구현 전에 확정 |
| 프롬프트·배점 로직 수정 = 앱 재배포 | **AI 프롬프트는 Edge Function(서버)에 보관** — 앱 재배포 없이 무중단 수정 |
| Play 자동 업데이트가 수정 배포를 흡수해 줌 | ⚠ **토닥 직접 배포엔 자동 업데이트가 없다** — 수정 1번 = 참여자 30명 수동 재설치. 대응: ① 배포 전 연구팀 시험 3일로 수정을 앞당겨 소진 ② **인앱 업데이트 배너**(앱이 version.json 확인 → "새 버전 받기" 버튼 → APK 다운로드) 1주차 구현 ③ 문구·콘텐츠 수정 소요는 서버화 검토 |

## 8-3. 동적 채움·기종 차이 대응 (2026-09-01)

**동적 채움 규칙** — "화면 한 부분만 코드로 바꿀 때 위치가 틀어지는" 사고 방지:
1. 코드는 **화면에 이미 있는 요소를 복제해 글자만 교체**한다. 새 마크업·새 스타일 생성 금지.
2. 목록(약·알림·대화)은 시안의 첫 항목을 템플릿으로 복제해 개수만큼 렌더.
3. 기능을 붙인 화면마다 **정렬·넘침 자동측정 스윕을 재실행**한다 (QA 하네스 재사용).
4. 극단 데이터 8종(긴 약명·병원명·이메일·말풍선 등) 주입 시험 통과 상태 유지.

**기종 차이 대응**:
- **글꼴 내장 완료** — Noto Sans KR 3굵기 전체(조각 124개, 3.6MB)를 APK·웹앱에 포함. 갤럭시·타 기종·아이폰 웹앱 모두 동일 글꼴로 렌더, 오프라인 동일. (APK 4.4→7.6MB)
- 렌더 엔진은 기종 불문 동일(안드로이드 WebView=크롬 계열)이라 "기종별 브라우저 차이"는 없음. 남는 변수는 화면 폭(360~430, 267건 검사로 커버)과 **시스템 글꼴 크기 설정**.
- 시스템 글꼴 크기(중장년 '크게' 설정)는 **따라가는 것을 기본**으로 하되(접근성), 2주차 실기기 점검에 **글꼴 크기 최대 상태 레이아웃 시험**을 포함한다. 깨지는 화면이 나오면 해당 화면만 보정.

## 9. 원칙 (변경 금지)

1. 위치(위도·경도)는 어떤 형태로도 서버에 보내지 않는다.
2. AI는 응급 여부·등급·악화/호전을 판정하지 않는다. 화면·프롬프트 모두.
3. 대화 원문은 연구 자료로 쓰지 않는다 (app_events에 건수만).
4. 사진 원본은 인식 후 즉시 폐기한다.
5. 키는 클라이언트에 넣지 않는다 (Edge Function 대리 호출).
6. 앱 문구와 실제 동작이 어긋나게 만드는 변경은 금지 — 어긋나면 문구가 아니라 설계를 고친다.
